# 시스템 아키텍처

## 개요

법원 증거 관리 시스템은 Flask 앱 팩토리 패턴을 기반으로 모듈화된 구조를 갖추고 있습니다.

## 모듈 구조

### src/web/ - 웹 레이어
| 파일 | 역할 |
|------|------|
| `app.py` | Flask 앱 팩토리 (`create_app()`) |
| `routes.py` | 레거시 라우트 (블루프린트로 이전 중) |
| `blueprints/` | 도메인별 블루프린트 6개 |

### src/mail_parser/ - 이메일 처리 핵심
| 파일 | 역할 |
|------|------|
| `processor.py` | 이메일 증거 처리 메인 클래스 |
| `mailbox_utils.py` | mbox 파싱, 스레드 그룹핑 |
| `evidence_generator.py` | 증거 문서 생성 |
| `forensic_integrity.py` | 포렌식 무결성 검증 |

### src/core/ - 공통 인프라
| 디렉터리 | 역할 |
|----------|------|
| `utils/` | 날짜, 해시, 텍스트 유틸 (정본) |
| `services/` | 공통 서비스 (정본) |
| `db_manager.py` | DB 연결 관리 |
| `settings_manager.py` | 설정 관리 |

### src/services/ - 비즈니스 로직
| 파일 | 역할 |
|------|------|
| `email_service.py` | 이메일 CRUD |
| `evidence_service.py` | 증거 관리 |
| `timeline_service.py` | 타임라인 생성 |

## 데이터 흐름

```
1. 사용자 → mbox 파일 업로드
2. EmailProcessor → mbox 파싱, 스레드 그룹핑
3. EvidenceGenerator → 증거 문서 생성
4. IntegrityService → 해시 체인 생성
5. TimelineGenerator → 타임라인 구성
6. 사용자 ← 증거 패키지 다운로드
```

## 엔트리포인트

| 파일 | 용도 |
|------|------|
| `src/runner/run_server.py` | 프로덕션 서버 (DB 초기화, 마이그레이션 포함) |
| `src/runner/app.py` | 의존성 체크 포함 실행 |

## 설정

- 앱 설정: `src/web/app.py:create_app(config_path)`
- DB 경로: `data/db/email_parser.db`
- 정적 파일: `static/css/`, `static/js/`
- 템플릿: `templates/`
